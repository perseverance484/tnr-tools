### Confirmed most consequential faults

1. **Wrong-target generation survived unchecked into user review.** At least two Particle Cannon tool-result descriptions named a hand-shaped energy burst or an atomic shield, contradicting the assistant's triangle-and-beam brief. This is directly visible generation-output evidence. The cause inside the image-generation service is **unverified**; avoid implying that an earlier model was definitely decoding a particular hidden prompt. The responsible studio still failed to reject the wrong subject *before showing it*.
2. **Isolation rule was not observed.** Multiple Aerathiel targets and many corrections were generated in one long thread; the director explicitly requested context reset, but the next generation stayed in the same thread. Even the FINAL `docs/workflows/ISOLATED_ART_GENERATION.md` says a studio coordinates while each subject has a fresh generation thread, with restart after two wrong-subject/composition errors.
3. **Symbol vs technique confusion.** Some candidates presented a magical golden artifact or floating triangle symbol, other candidates a generic shield/vortex. The eventual successful Particle Cannon was driven by director's *front-facing “eclipse” camera angle*: triangle is the **firing aperture silhouette**, high-energy core emits one beam straight at the viewer. Composition/perspective solved what repeated adjective-heavy prompt revisions did not.
4. **Body anatomy failed exactly as director predicted.** An optional caster-hand exception produced six visible fingers. The user's anatomy warning was specific and justified; anatomy should not be reintroduced merely because an assistant considers it narratively appropriate.
5. **Visual register drift appeared when dramatic effects substituted for geometry.** Early Atomic Shield raw candidates became glossy fantasy illustration, and later Particle Cannon attempts became wizardly ornaments. The winning icons use crisp premium pixel-art edges, compressed turquoise particle wind, deep navy space, restrained pale gold and strong silhouette hierarchy.
6. **The “icon sheet” was generated rather than composited.** The earlier `aerathiel_jutsu_icon_showcase.png` (PNG 1448×1086, SHA-256 `b4161df5d65d1187eab0b602cfee818c988381880d6173a20259fd5a97d0d213`) was an ImageGen-created approximation. It cannot prove approved pixels were retained and is **INVALID** under `docs/workflows/JUTSU_ICON_SHOWCASE.md`. The actual locally assembled five-tile 3+2 sheet uses the exported exact approved WebPs, with each tile proven pixel-equal to the logged LANCZOS resize. It still requires **new director acceptance** of that exact deterministic sheet.

## Recommended updates — ranked by leverage

### P0 — Visual quality / accuracy: extend the existing isolation protocol (director approval required)

**A. Add an explicit TARGET LOCK / brief-application gate.** Before a generator call, the per-jutsu brief must encode: immutable `bloodline ID + jutsu ID + display name`, source-supported technique action, **one unique dominant silhouette**, camera/perspective, one secondary effect, style reference roles, and exclusions drawn from the other family icons. A short checklist is enough. After the result is rendered, independently inspect whether the actual candidate depicts the target; if the tool's generation description or image depicts a different jutsu, reject it in-session and do **not** ask the director to critique a wrong target. **Do not claim we can inspect or control hidden generator prompt construction if the UI does not expose it.** A static brief-text linter can catch missing fields; *only inspection of returned pixels* can confirm visual identity.

**B. Mandatory composition/perspective FIRST, rendering SECOND.** For a high-identity technique, lock “what the shape does and where it points” before palette or particles. If two candidates show the wrong subject/composition, **close the isolated generation conversation and start a fresh one** with exactly the original jutsu art (identity-only) and a single director-approved family original (style/material-only). Do not use the rejected images as positive conditioning or keep stacking longer negative prompts. This reaffirms an existing rule rather than changing authority.

**C. Family-distinctness fail-fast gate.** Before user review, compare every candidate against the **five reserved primary silhouettes**, not merely the target's description. Check primary geometry and action at **125, 64 and 32 px**. **Hard reject** if the image could reasonably be read as a second previously approved technique, as happened with Decaying Touch / Windshear and Particle Cannon / Atomic Shield. Repeat only the failed target, never a previously approved icon.

**D. Default technique-first, no anatomy.** No full body, face, hands, fingers or limb fragments unless demonstrably necessary *and explicitly approved by director for that exact target*. A five-digit handprint may be a deliberately approved abstract technique silhouette, **not** blanket permission for anatomy elsewhere. If actor/hand inclusion is explicitly allowed, count digits (five per normal hand, correct thumb placement) and check proportions before showing it; an anatomical failure means discard the candidate and normally return to actor-free presentation. Never reinterpret general family approval as permission to add humans.

**E. Chakra, not magical artifact.** A closed triangle can be a legitimate main shape when it is materially integrated into the jutsu's *firing aperture*. Do not ban triangles categorically; ban decorative frames, runes, polished gold corner ornaments, geometric sigils, floating isolated glyphs and spell-circle motifs unless the technique explicitly owns them. A frontal three-sided charged-pressure launch aperture and near-camera beam is the successful Particle Cannon reference. Preserve the director's adopted identity, not an arbitrary general physics vocabulary.

**F. Gallery generation is a separate non-generative work mode.** When the director requests an “icon sheet,” “family showcase,” or “closeout collage,” **NEVER use a generative image tool to remake approved tiles**. Use only exact approved processed binary assets, stable deterministic compositor layout (3+2 for Aerathiel), actual decimal kB captions, hash manifest and pixel-equality assertions for every tile, plus thumbnail QC. A generative gallery must be classified **INVALID / NOT_ACCEPTED**, never counted as an approved family sheet. If any source changed, invalidate the old gallery and request fresh signoff on exact new pixels.

### P1 — Faster sessions without lower quality

**G. Standard single ZIP intake + batch source check.** Already documented in `docs/workflows/BLOODLINE_JUTSU_ICON_STUDIO.md`: one supplied original ZIP, safe hash/decoder/ID mapping, one family visual card, N independent silhouette allocations **up front**, and first isolated brief. Do not ask the operator for screenshots or duplicate inputs already in the ZIP. Read repository canon once in a batch at startup, then only delta/check current ref at milestones.

**H. Keep two actual images per isolated generation maximum.** Exact original for *identity only* + one available approved family raw for *style only*. Do not feed earlier wrong compositions or large contact sheets; don't claim a reference image was seen when only its path, hash or URL was passed. Source-style pixel library should be committed with provenance by appropriate branch owner when the director supplies final exemplar ZIPs (still not verified present in current main).

**I. Batch export only after N/N raw approvals.** The local Aerathiel export took approximately **1.3 seconds** for all five 1254px raw PNGs to 256² lossless VP8L. Local pixel equality, source hash, ZIP member CRC, WebP codec, 125/64/32 QC and source-faithful gallery were checked. This **does not measure image generation latency** and the canonical `artpreflight.py --type JUTSU_ICON` remains NOT_RUN in the current session. Keep source archive and small flat WebP archive separate for mobile.

**J. Add failure statistics distinct from technical timers.** Beyond cold startup, ZIP decode, export and gallery durations, log `attempt_count`, `wrong_target_count`, `silhouette_conflict_count`, `art_style_drift_count`, `anatomy_rejection_count`, `approved_raw_after_attempt_n`, and `generator_wait_ms` **only where measured**. Pre-fill successor briefs from the studio ledger; don't repeat unrelated repo reads on every warm turn. A faster export does not solve six bad image generations.
