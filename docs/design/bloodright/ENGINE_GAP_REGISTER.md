# Bloodright engine-gap register

**Status:** planning record, separate from the design deliverables. Nothing here is implemented. Source facts are read at `studie-tech/TheNinjaRPG@16498fd776fad9c91e4b84efed4380fe3a487050` (see `evidence/SOURCE_MECHANICS.md` for line citations); `origin/main` of the game repository equalled that pin when read on 2026-10-03. Per-bloodline dependencies are tabulated in the generated `CLASSIFICATION_DEPENDENCIES.md`.

Evidence tiers follow `docs/00_INDEX.md`: **source-verified** unless marked.

|---|---|---|---|---|
| G1 | Whole-kit potency classification | `resolvePotencyTags` matches each effect row's own `elements` (absent → `["None"]`) against a modifier's `affectedElements`; `affectedTag` selects the tag. There is no per-jutsu or per-bloodline classification field (`validators/bloodline.ts` has none). | Add a potency classification lookup (per jutsu, derived from its bloodline) that the resolver consults **for eligibility only**, leaving each row's combat `elements`, targets and stat filters untouched. Without it, element-less buff/debuff rows are reachable only through `None`, which also reaches every non-elemental row the player casts. | Every tree (all 44 including the reference). |
| G2 | Classification exclusivity | Within the 95 captured kits: Sand, Boil and Metal are exclusive; Scorch (2), Dust (3), Magnet (2), Wood (2), Crystal (2), Explosion (2), Lava (2), Storm (4), Light (7), Ice (8), Yin-Yang (9), Shadow (14) are shared; basic elements appear on dozens of kits; 17 approved kits have no usable element at all (None-only, basic-element-only or multi-element damage rows). Request a read-only public jutsu listing with effect rows to close the ordinary-jutsu leakage audit. | Scope statement of every tree; design values assume no leakage. |
| G3 | Bloodright Points and silver | `purchaseSkill` spends `user.skillPoints` against `costSkillPoints`; no second currency, no silver purchase path, no per-section cap. | A separate BP ledger (acquired with silver, cap 4), a purchase path that spends BP for Bloodright entries and SP for ordinary entries, and the price/gate decisions in `OPEN_DECISIONS.md`. Do not spend ordinary SP. | Implementation of any tree. |
| G4 | Current-bloodline gate and swaps | Activated skills are realized for every battle regardless of bloodline (`combat.ts` 3072–3115); folders are presentation only; bloodline swaps do not touch `UserSkill`. | Server-side eligibility at purchase (owning bloodline matches the section) and at realization (skip entries whose bloodline is not the current one), plus the retention/refund rule on swap. | G7 | Repeated rows, injected children, item gates | The resolver loops every supported row, so two matching rows on one jutsu both gain the modifier (counted separately in every audit). Item-gated jutsu (`requiredBloodlineItemId`) are counted in coverage but need the item to be cast. | Decide whether injected children inherit the parent bloodline's classification (affects Ethereal Monarch's Stardust, Shiroi Youso's five generic children, Reptilian's summon child). Baselines for children must use the inject level, not 25. Item-gated coverage is flagged per tree. | Ethereal Monarch, Shiroi Youso, Reptilian (injection); Blood-Enchanted Eyes, Blue Blade Eyes, Godstorm Eclipse, Tetsugan (gates). |
| G8 | Ranked modes | Skill-tree and bloodline effects are not added in `RANKED_PVP` / `RANKED_SPARRING`. | Bloodright inherits that exclusion unless the user decides otherwise; no engine change is proposed here. | None (product decision). |
| G9 | Stacking and clamps | `BATTLE_TAG_STACKING = true`: potency modifiers from several sources all apply; each percentage modifier clamps at 100, flats do not. UI work, not resolver work. | Presentation. |
| G12 | Tree presentation and sections | `SkillTree` has `folderId` and `tier` only; no notion of a per-bloodline section. | One folder per bloodline (hidden until release) plus a UI filter to the current bloodline; tier values map Foundation/Hidden/Advanced. | Presentation. |

| G14 | Adverse rows | Dai Kenja's Overloaded Impact carries a self-targeted Increase Damage Taken row; a potency node on that tag raises it too (resolver cannot exclude a row by jutsu). | Either accept and keep the flat small (as the draft does), avoid the tag, or add a per-row opt-out flag (engine extension, not proposed). | Dai Kenja. |
| G15 | Stat filters on element-less rows | `getEfficiencyRatio` (tags.ts 3477–3510) pushes `None` into the tag list of any effect whose `elements` is empty — for the damage effect and for the modifier alike — and returns 1 on any overlap. A buff/debuff row with `statTypes` but no element therefore matches every element-less damage effect of any stat type (basic attacks, non-elemental jutsu and weapons) and excludes only elemental damage of a non-listed stat type. 186 of the 192 stat-filtered supported non-damage rows across the 44 dossiers have no element. | No engine change proposed. Tree prose must not describe a stat filter as binding when the row has no element ("Ninjutsu or non-elemental damage", not "Ninjutsu only"), and downstream-benefit and adverse-trade reasoning must use the real matching. The kit dossiers do not yet print stat filters or this fallback (tooling debt in `audit_kits.py`). | Coverage prose of every tree whose buff/debuff rows carry a stat filter and no element; Dai Kenja risk 1 (corrected in Draft 2). |
| G16 | Efficiency ratio for `Highest`-stat damage rows; friendly-fire default; ground-spawn placement | `getEfficiencyRatio` (tags.ts 3477–3510) replaces `Highest` in `statTypes` with `getStatTypeFromStat(e.highestOffence)`, and `realizeTag` (tags.ts 75–115) copies `highestOffence` from the **casting** user onto damage effects and modifiers alike; `getLowerGenerals` (tags.ts 3407–3414) pushes nothing for an absent/empty `generalTypes`; an empty element list pushes `None`. A buff/debuff row listing all four stat types and no element therefore returns ratio 1 against every damage effect whose stat resolves to one of the four or that carries no element (Blood-Enchanted Eyes: 10 of its 11 supported buff/debuff rows), while an element-only row (Sanguine Plague IDT: Fire/Lightning/None/Shadow/Water) matches same-element and element-less damage but not off-element elemental damage. `checkFriendlyFire` (process.ts 154–183) treats an absent `friendlyFire` as `ALL`, so an AoE debuff row without the field also lands on allies in the area; ground effects are re-applied every round as one-round user effects to whoever stands on the tile (process.ts 323–340) and `move` sorts last (util.ts 1218), so an EMPTY_GROUND spawn with a move row reaches the caster from the round after the cast. | No engine change proposed. Reads performed for Blood-Enchanted Eyes Draft 2 (risks 6–7); other trees with `Highest`-stat damage rows, stat-filtered modifier rows, or AoE buff/debuff rows lacking `friendlyFire` should cite these lines instead of describing the question as unauditable, and should name ally-adverse AoE deliveries. Not read: whether `BattleUserState.highestOffence` is always defined (an undefined value pushes the literal `Highest`, which matches nothing). The kit dossiers do not print `friendlyFire` or resolved AoE recipients (tooling debt in `audit_kits.py`). | Coverage and ally-adverse prose of every tree with AoE buff/debuff rows or `Highest`-stat damage rows; Blood-Enchanted Eyes risks 6–7. |
