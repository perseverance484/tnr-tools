## Universal style lock / acceptance gates

- Freeze the three user-approved symbol silhouettes: **Foundation = nested elongated diamond; Hidden Art = pointed diamond with curved side arcs and horizontal crosspieces; Advanced Art = pointed starburst surrounding the nested diamond**. Do not reinterpret shape based on bloodline; only modify color, material, interior texture and controlled glow.
- **Solid near-black / black background** is the user-approved BEE baseline. One centered emblem per image, clean negative space, no words, scene, border/UI, stray ornaments, characters or simulated infographic.
- For a new bloodline: (1) open **2–4 exact jutsu icons** and its bloodline identity art where available, capture source/approval metadata, (2) approve a short visual-treatment card, (3) generate **Foundation first**, (4) user approval locks palette/material, (5) generate Hidden + Advanced against Foundation, (6) side-by-side three-icon QC and neighboring bloodline comparison, (7) process/export/preflight all three.
- Relevant icon spec: `skills/producing-tnr-art/data/25x_DATA_art_spec.json` `targets.ICON` on main: square, **256×256 WebP lossless** target, working cap **460,800 bytes (450 KiB)** and upload hard cap **524,288 bytes (512 KiB)**; inspect at ~125 delivered pixels and smaller 64/32px legibility previews. The eventual Bloodright UI may need its own client-field verification; ICON is the current working production target, not a proven future Bloodright renderer contract.
- Keep opaque background versions; verify precisely that original glow and fine edge definition survive resizing. Record filename, dimensions, byte size, asset input and hashes as real files become available. **File-size alone is not full preflight**.
- **Art approval ≠ upload-ready QC ≠ live publish.** New corrected output uses a fresh versioned filename; never overwrite cached upload names.

## Priority order and why

- **Wave 0** — approved baseline: BEE, finish only its processing/preflight.
- **Wave 1** — calibrate palette/material range: sapphire/ice, confirmed teal/cyan ether, and solar reference; verify missing existing-jutsu pixels before production.
- **Wave 2** — S/H flagship/high-complexity cases: multi-element, cosmic/light, shadow, sand and metal. These test distinctiveness under the same geometry.
- **Wave 3** — A-rank material variety: Scorch, Crystal, Lava, Boil, Wood and Explosion, minimizing style drift across different textures.
- **Wave 4** — abstract motifs: Shadow and Yin-Yang bloodlines, where a generic sigil treatment could accidentally merge identities.
- **Wave 5** — direct comparison pairs: Storm, Ice, Magnet and Dust. First collect both members' art references; finish one complete set at a time with a clean image-generation context and compare the pair before locking either. These are ordered late to avoid mistaken palette copying.

## BEE upload processing evidence — 2026-10-08

The approved black-backed raw PNGs were resized using Pillow Lanczos and exported in lossless WebP/VP8L. Outputs checked: 256×256, exact lossless pixel equality to the corresponding resized source, under 460,800 bytes, nearly-black corners, all 3 tiers legible at 125px/64px/32px, ZIP member byte equality/CRC PASS. Source/output SHA-256 values and actual byte sizes: [BEE_ICON_OUTPUT_QC_20261008.json](BEE_ICON_OUTPUT_QC_20261008.json).

**Explicit unresolved contract conflict:** current `skills/producing-tnr-art/scripts/artpreflight.py` checks `targets.ICON.chroma_key != null` and requires image mode RGBA. The user specifically selected opaque black-background BEE icons, which are RGB. Therefore all three would trip an **alpha** error in the canonical preflight. A byte-cap pass is not a zero-error preflight; document the opaque-background art-direction exception rather than adding artificial alpha or rewriting canonical spec. No game upload/readback was performed.

## Reference collection policy

- Collect **exact imagery**, not just matching names. The kit dossier is a guide to which jutsu belong to the bloodline, not evidence that those images were seen.
- When a former image reference is not stored in the repo (such as current-chat artwork), mark `conversation evidence; materialization pending` rather than inventing a persistent location.
- Do not use Bloodright poster art as a mechanically authoritative source; poster visuals can help art style only. Keep artistically confirmed teal/cyan Ethereal Monarch distinct from older purple guesses.
- Do not reclassify any excluded/deferred record as approved based on a visible icon or rank alone.
