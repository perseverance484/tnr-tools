# B. Builder to Forge parity and retirement gates

**Status:** planning. This section answers one question with evidence: *what would have to be true before the Builder can be retired?* It does not retire anything, and it does not set a date. Retirement timing is the director's (K-11).

**Scope.** Sixty-one capability rows cover every meaningful behaviour of `builder_bundle.js` v4.32 and `forge/src` 0.4.0 at `main@305a28f`, plus ten derived retirement gates with measurable acceptance. Rows carry the ids `P-01` to `P-61` and `G-01` to `G-10`; sections C, G, H and J cite them by id. The Builder is not deprecated, modified or removed by this package (brief section 16).

## B.1 Method, evidence tiers and what was verified

Three independent readers inventoried the Builder (the whole 892-line bundle), Forge (35 modules) and the committed record (42 results bundles, 41 manifests, 23 generator scripts). A merge agent built one row per capability and, wherever the inventories disagreed or a cell was unsupported, re-opened the cited source and settled it with a citation. Then one adversarial verifier per decisive row re-read every cited location with instructions to default to `CORRECTED` or `REFUTED` unless the source says exactly what the row claims, and to hunt for evidence the row missed.

Evidence tiers follow `docs/00_INDEX.md`. **Source-verified** means a file and line read in this pass at `main@305a28f`, in `builder_bundle.js`, or in the named game-source checkout (Forge pin `345d18ac`, head `36c5873b`). **Behaviour-proven** cites a committed bundle under `harvests/inbox/`. **Observed** is a count or a measurement re-derived in this pass. Nothing was run against a live game host, and no game source was executed.

Verification scope. A row is verified when a wrong cell would change a conclusion the package rests on: every `GAP`, every `INTENTIONAL DIFFERENCE`, every retirement blocker, and every row the merge marked low or medium confidence. Rows outside that set (high-confidence `PARITY` and `FORGE BETTER` rows that block nothing) carry `not verified` in the last column and should be read as the merge agent's finding, not as an audited one.

Verification status at this SHA: **not verified** 61.

In plain language: Forge is the safer tool on 24 of 61 capabilities and matches the Builder on 10 more, so the direction of travel is not in question. But 22 capabilities have no Forge path at all, and 7 of those are proven, load-bearing parts of how content actually gets made or recovered today. The Builder cannot be retired while any of them is missing, and no schedule can substitute for building them.

The pattern in the hard blockers is worth stating once: they are not exotic features. They are **how packages arrive** (zip packs with their byte ledger), **how research is read** (procedures outside the audited registry, paged list reads, exported bodies), and **what happens when a run goes wrong** (retry a failed step, re-run a finished manifest without duplicating creates). Forge was built to make writes safe; the Builder is still the only tool that can read broadly and repair.
