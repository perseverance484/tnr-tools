## C.0 Scope

This section is an inventory of the content workflows that actually run in this repository, with three facts per workflow: evidence that the workflow is real (a committed bundle, manifest, workstream task or state entry), the tooling that exists for it today, and what Forge 0.4.0 does with it (supported, partial, refused). It exists so that the information architecture in section D, the roadmap in section G and the retirement gates in sections B and J are fitted to measured work rather than to a candidate tab list.

What it is not: it is not a parity matrix (section B owns capability-by-capability parity), not a Content Admin source audit (section E), not a lane taxonomy (K-24 is open; C.3 only groups rows as an input), and not a proposal to move any repository-canonical script into the browser (C.6; `RUL-2026-09-12-002`). Design-lane workflows A to R (WCM:128-559) and channels A to P (EXP:186-799) are cited by id as the design view of the same work; where they describe capability that does not exist, the row says so rather than adopting it.

## C.1 Method and evidence tiers

1. Every committed results bundle (42) and manifest (41) was read by the harvest reader of the deep dive; counts quoted below are re-derived from those files and carry the tier **Observed** unless a specific bundle is named, in which case the fact is **Behaviour-proven**. The reader's rows are committed as `evidence/harvest-evidence.json` (section 00.5); the underlying files are `harvests/inbox/tnr_results_*.json`, `push/*.json` and `archive/spent-manifests/**`.
2. Tooling existence follows the three-way test the reconciliation plan asked for: **EXISTS** (file on `main@305a28f`, cited), **EXISTS ONLY ON 824c4d58** (file only on the ChatGPT foundation branch), **DOES NOT EXIST** (no file anywhere; a proposal). Code claims are **Source-verified** at the cited line.
3. Forge support is stated per parity row (`P-nn`), which the adversarial verifier confirmed or corrected (section B carries the tally); the per-row verdicts were still being re-verified when this section was written, so any row that later changes is corrected in section B first and here second.
4. Tier labels in the tables: SV = Source-verified, BP = Behaviour-proven, OBS = Observed, INF = Inferred. Tiers are never upgraded here; a claim that could only be settled in a browser or live session is INF.
5. Actor vocabulary follows `docs/DOCTRINE.md:75-79` (the user taps; agents push git) and `docs/workflows/CONTENT_WORKSTREAM.md:44-71` (a task carries a `lead_role`): **content agent** (Claude/ChatGPT session producing manifests, packets and verification), **operator** (the user driving Builder/Forge on device), **content admin** (the reviewer who gives the go-ahead), **director** (the user ruling on reserved decisions), **art partner** (ChatGPT image production under `docs/workflows/ART_PRODUCTION.md`), **automation** (GitHub Actions).
