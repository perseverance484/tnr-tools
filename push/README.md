## 111–119 Bloodright kit-classification edit (stage 2, RUL-2026-10-18-003)

Generated by `push/111_bloodright_classification.gen.py` from the push/109–110 results; do not hand-edit.
Each jutsu entry changes `elementClassification` from `None` to its tree element. `injectableInBattle`
is re-sent at its captured value (law 20).

**Before-image check:** `scaleUserStats` from the game source, run offline on all 46 captured AIs,
moves no stat on a no-change save. Every AI is at its level budget.

**Run in this order:**
1. `111_..._probe.json`: 1 AI, 1 jutsu. **Run 2026-10-18**, all 3 entries VERIFIED
   (`harvests/inbox/tnr_results_1792360863823.json`).
2. `119_..._probe_readback.json`: read-only `profile.getAi` of the probe AI. Forge's verify covers only
   the asserted keys, so this full read is compared against the before-image. Return the results
   before running 112.
3. `112`–`115` (`ai_linked_1`–`4`): each runs in three phases: unequip the affected jutsu, set the
   classification, re-equip the exact original kit (laws 18, 60). Forge honours the phases.
   `validate.py` warns "jutsu appears after a later phase" by design. That order is law 60.
   Each ends with a full `profile.getAi` read-back of its AIs (capture `after`).
4. `116`–`118` (`unequipped_1`–`3`): the 84 kit jutsu no AI equips; classification edits only.

Run 112–115 back to back, so the AIs are only briefly without those jutsu. Return every results
bundle. Each read-back is checked with
`python3 scripts/bloodright_classification_readback.py <results.json>`, which compares every column,
the kit (level, experience, equipped) and the items against the push/109–110 before-image.

**Not covered:** 4 AIs were created after the 2026-10-12 census (522 → 526 live). Only Sealwright is
known to the repo. If any of the others equips a kit jutsu, it needs a re-equip after these runs.
