# Jutsu text: descriptions and battle lines

How to write a player jutsu's `description` and `battleDescription` so they match what the
jutsu does. Use it for new jutsu and for text fixes on live ones (suggest mode, one record per
suggestion). Engine facts below were read in studie-tech/TheNinjaRPG@a744c04; file and line
are cited so they can be re-checked on a newer commit.

## 1. What the player sees

| Text | Where | Notes |
|---|---|---|
| `description` | jutsu card, training and shop lists | Rendered as HTML (`layout/ItemWithEffects.tsx:767`). |
| Effect list | same card, under the description | Generated by the game from `effects`: one line per effect with its own wording, power and rounds (`ItemWithEffects.tsx:1332-1378`). **The player already sees the numbers**, so the description does not repeat them. |
| `battleDescription` | combat log, each cast | Shown as `<jutsu name>: <line>`, plus ` on <b><tile></b>` when the target tile has a name (`libs/combat/actions.ts:1271`). The name is already printed, so the line never needs to name the jutsu. |

## 2. Read the record first

Write from a fresh capture of the live record, never from the name. For each jutsu note:

- **Who it reaches:** `target` (`SELF`, `OPPONENT`, `OTHER_USER`, `ALLY`, `CHARACTER`, `GROUND`,
  `EMPTY_GROUND`) and `method` (`SINGLE` one unit; `ALL` everyone it may reach; `AOE_*` a shape
  on the field: circle, line, wall, spiral).
- **Each effect's own target.** An effect with `target: "INHERIT"` lands on whoever the jutsu hit;
  `"SELF"` lands on the caster whatever the jutsu targets. A damage jutsu with a `SELF` buff
  hits the enemy *and* strengthens the caster; say both.
- **What each tag does.** Use the game's own wording (`validators/combat.ts`, the `description`
  of each `*Tag`) and the table in section 5. Do not guess from the tag name.
- **Duration.** `rounds: 0` is instant; `rounds: N` lasts N rounds. Buffs and debuffs start the
  round after the cast (`tags.ts` handlers skip `isNew` / `castThisRound`); damage is immediate.
- **Element and weapon.** `elements` on damage/pierce and `jutsuWeapon`. The text must not name
  a different element or weapon. `Storm`, `Ice`, `Dust` and the other combined elements are
  elements in their own right.

If an effect looks wrong (a buff landing on the enemy, a heal that cannot reach anyone), that
is a mechanics finding: flag it and leave the effects alone. A text ticket changes text only.

## 3. Description

- One or two sentences, roughly 80 to 220 characters.
- Say what the technique **looks like** and what it **does**, in that order or woven together:
  "Within the user's domain, water answers to them alone. It rises to crush their foe, then flows
  back to its master, deepening their healing for a short time." (Water's Domain, director-approved)
- Cover every effect the player will notice. A secondary effect can be a clause; it cannot be
  missing, and nothing may be claimed that the effects do not do.
- Never contradict the reach, but only state it when it changes how the jutsu is used: an area
  blast, an ally, the user. A single target is the default; do not announce it with stock phrases
  like "one foe" or "a single foe". Vary the wording from jutsu to jutsu.
- Words, not numbers: "for a short time", "lingering", "heavily". The card shows the values.
- Plain present tense, third person ("the user", "the target"). No "you", no lore dumps, no
  jokes that hide what the jutsu does, no build notes or staff abbreviations.
- No em dashes (the validator flags them). No franchise names or borrowed signature lines.

## 4. Battle line

- One sentence, two at most, present tense, starting with `%user`.
- `%target` is replaced only by the units an `INHERIT` effect actually reached
  (`actions.ts:1095`, `:1121`, `:1334`). Use it only when the jutsu hits a unit. On `SELF` it
  prints the caster's own name; on `GROUND` / `EMPTY_GROUND` with nobody hit it prints the
  literal text `%target`. For those, write the line without it ("%user dashes across the
  field").
- **`%jutsu` is not a placeholder.** Nothing in the source replaces it; it prints literally.
  Remove it wherever it appears.
- **Avoid the gendered placeholders** (`%user_subject`, `%user_posessive`, `%target_subject`,
  ...). They are wrong in the current source: `%user_posessive` gives "hers", `%target_subject`
  gives "himself", and every gender other than Male gets the female form (`actions.ts:1272-1330`).
  Write "their" or rephrase.
- Describe the visible action and its result, in step with the effects: if the jutsu also
  buffs the caster, the line shows that too.
- Ends with a full stop. No trailing spaces, no doubled spaces.

## 5. Tag wording

The game's own wording, with the reading to use in text. `target` here is the effect's
recipient after section 2.

| Tag | Game wording | Write it as |
|---|---|---|
| `damage` | Deals damage to target | strikes, burns, crushes (match the element) |
| `pierce` | Deals piercing damage to target | cuts through defences, ignores protection |
| `increasedamagegiven` / `decreasedamagegiven` | Increase / decrease damage given by target | empowers / weakens the recipient's attacks |
| `increasedamagetaken` / `decreasedamagetaken` | Increase / decrease damage taken of target | leaves the recipient exposed / hardens the recipient |
| `increasestat` / `decreasestat` | Increase / decrease stats of target | sharpens / dulls the named stats |
| `increaseheal` / `decreaseheal` | Increase / decrease how much target can heal others | strengthens / weakens the recipient's healing (heals, lifesteal, vamp) |
| `heal` | Heals themselves or others | mends, restores health |
| `absorb` | Absorb damage taken & convert to health, chakra or stamina | turns incoming blows into the named pool |
| `lifesteal` | Heal based on damage given | heals the user from the damage dealt |
| `shield` | Creates a temporary HP bar | raises a barrier of temporary health |
| `wound` | Wound damage over multiple turns based on damage dealt | leaves a wound that keeps bleeding |
| `afterburn` | Take a percentage of incoming damage as afterburn damage | sets the target smouldering: hits it takes burn on |
| `poison` | Deal damage based on Chakra and Stamina lost | poisons: punishes spending chakra and stamina |
| `drain` | Drain target's pools over time | saps chakra / stamina / health each round |
| `recoil` | Recoil damage given back to self | the user takes part of the blow back |
| `reflect` | Reflect damage taken | turns part of incoming damage back on the attacker |
| `stun` | (handler, `tags.ts` `stun`) | may stagger the target (power is the chance), costing it action points; say "can stun", not "stuns" |
| `move` / `moveprevent` | Move on the battlefield / Prevents movement | repositions the user / pins the target |
| `cleanse` / `clear` | Clears all negative / positive effects from the target | washes off debuffs / strips buffs |
| `buffprevent` / `debuffprevent` / `cleanseprevent` / `clearprevent` / `healprevent` / `stunprevent` | Prevents buffing / debuffing / ... | seals the recipient against that |
| `increasepoolcost` / `decreasepoolcost` | Increase / decrease cost of taking actions | makes chakra and stamina costs heavier / lighter |
| `rob` | Robs money from the target | steals ryo |
| `summon` | (handler) | calls the named creature to fight |
| `visual` | none | cosmetic only, never mention |

For a tag not listed, read its `description` in `validators/combat.ts` and its handler in
`libs/combat/tags.ts` before writing.

## 6. Suggest-mode ticket checklist

- [ ] Fresh capture of the record (no older than the last edit to it you know of).
- [ ] Not equipped by any AI in the latest census (laws 18, 60); if it is, flag it instead.
- [ ] No other suggestion is open on the record: approving one makes the other OUTDATED, so a
      text fix and an icon for the same jutsu go one after the other.
- [ ] `data` carries only `description` and/or `battleDescription`, plus `injectableInBattle`
      at its live value (law 20).
- [ ] The item's `suggestion.rationale` names what was wrong with the old text and what the new
      text now matches (RUL-2026-10-19-007).
- [ ] `validate.py --strict` and `forge/tools/check_manifest.mjs` both pass.
